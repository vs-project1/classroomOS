## Design Specificity Verdict

**LLM assessment:** Partially authored — a real school domain wearing a rented admin-template costume. The substrate is genuinely Nepali-college-specific: Asia/Kathmandu timezone everywhere, TU FOHSS / BCA Program identity in chrome, admin-provisioned account model, .edu.np placeholder email, and the attendance What-If simulator could belong to no other product. But presentation keeps collapsing into category furniture: "Command Center" hero, generic indigo shadcn-admin shell, stock pravatar avatars, enterprise jargon ("Quarantined", "Provision identities"). Worst, fabricated data (fake uploads, hardcoded stats, dead buttons) actively anti-authors the product.

**Deterministic scan:** 2 CLI findings — both `gray-on-color` warnings at `src/app/(student)/subjects/[id]/page.tsx:308` (`text-slate-700` and `dark:text-slate-300` on bg-amber family). ## Overall Impression

Solid bones, broken promises. The accounts console, Today page, and attendance barometer prove the team can build genuinely excellent Operate UI. Everything around those peaks ships unfinished organs: a permanently disabled Grade button, dead buttons, fake uploads, counters capped at 1 by `limit: 1` queries. The single biggest opportunity: stop fabricating, finish wiring — trust compounds across every screen.

## What's Working

1. **Accounts console** (`admin/accounts`) — search + role/status filters, live KPI cards, self-protection ("You" badge, can't deactivate yourself), monospace temp-password handoff dialog with Copy button. A real daily-operations tool.
2. **Today's Schedule** (`student/today`) — tri-state class cards (ONGOING pulse / COMPLETED / UPCOMING), 7-day strip selector, role-adaptive deep links that prefill Log Session — working-memory relief done right.
3. **Attendance barometer + What-If simulator** (`student/attendance`) — turns the high-stakes 80% number into agency; correction dialog with clear success state; "Safety Buffer" copy.

## Priority Issues

1. **[P0] Fabricated UI breaks trust.** Fake file upload writes `https://utfs.io/f/mock-*` — attachments never upload (`homework-client-workspace.tsx`); hardcoded "22 Credit Hours" (`admin/subjects/page.tsx:34-36`); dashboard counters are `.length` of `limit: 1` queries so never exceed 1 (`admin/page.tsx:33-42`); pravatar stock avatars; dead buttons (Sync Deadlines, Browse Course Catalog, Export Roster). Fix: wire uploadthing (already a dependency), compute counts with aggregates, remove unwired buttons, render "—" for unknown data.
2. **[P0] Broken navigation and dead-end flows.** Teacher sidebar links to non-existent routes (`navigation.ts:35,37` → `/teacher/classes`, `/teacher/assignments`); saving a teacher redirects to 404 (`teacher-actions.ts:106` → `/teachers`); admin assignment creation dumps into student `/homework` (`assignments.ts:270`); "Grade Now" is a permanently disabled placeholder on the teacher's core page (`grading/page.tsx:87`). Fix: correct/revalidate paths, ship minimal grading detail route or remove nav entries until built.
3. **[P1] High-stakes actions lack guardrails.** Attendance pre-marks every student "present" (CR log-session + sessions/new) — lazy submit falsifies records feeding the 80% mandate; account deactivation is one click, no confirm; routine slot deletes instantly; `deleteTeacher` swallows FK errors silently; `currentPassword` is schema-optional so new password can be set without proving identity (`auth.ts:110,170`). Fix: unmarked default + bulk-mark helper, styled confirm dialogs naming consequences, surface action errors, require current password.
4. **[P1] Hover-gated invisible controls.** `opacity-0 group-hover:opacity-100` wraps Edit/Delete/status actions across teachers, homework, notices, events, students, routine — unreachable on touch, focus-invisible for keyboard users. Fix: always-visible ghost icon buttons or visible row overflow menu.
5. **[P1] No route-level states anywhere.** Zero loading/error/not-found files under src/app; all pages force-dynamic server renders — navigation freezes then pops, DB failure = Next crash screen, successes redirect silently with no confirmation (password change ends on an emotional cliff). Fix: add loading skeletons per segment (ui/skeleton exists unused), error.tsx boundaries, success interstitials/toasts.

## Persona Red Flags

**Alex (impatient power user — staff):** No bulk actions anywhere (50 deactivations = 50 clicks + confirms that don't exist); students/teachers lists lack the search the accounts console has; grading queue unfilterable; hover-to-reveal slows every repeated row operation.

**Sam (accessibility-dependent):** Focusable-but-invisible hover controls (opacity-0); sessions table has no `<thead>` so screen readers get no column headers; fixed light-mode `bg-red-50 text-red-800` error alerts near-illegible in dark mode; icon-only delete named only by `title`; dark-mode FOUC flashes wrong theme every load.

**Casey (distracted mobile user):** Two simultaneous mobile nav systems whose bottom bar overlaps content (`pb-safe` is a no-op utility, main padding 32px < nav height 64px); primary CTAs are h-8/h-9 (under 44px touch target); attendance requires 50 individual select interactions one-handed; late-submission consequence never warned before it happens.
