## 2. Logic Chain
1. *Scrypt Hashing Standard*: By using 16-byte random salt and 64-byte key length with colon delimiter `${salt}:${derivedKeyHex}`, password hashes in `password.ts` match the hashes generated by `src/db/seed.ts`, ensuring all seeded users can authenticate immediately.
2. *Stateless Session Tokens & Edge Runtime*: Using HMAC-SHA256 signed payloads `${userId}.${role}.${mustChangePassword ? 1 : 0}.${expiresAt}.${signature}` allows Next.js Edge middleware to verify signatures and enforce quarantine/RBAC in 0ms without hitting the SQLite database or causing `SQLITE_BUSY` contention.
3. *Dual-Layer Defense*: Deep server component verification in `getCurrentUser()` / `requireAuth()` queries the database to confirm the user account is active, hydrating linked student/teacher records into `SessionUser`.
4. *Quarantine Flow*: New accounts provisioned by administrators are marked `mustChangePassword = 1`. Middleware intercepts navigation to any route other than `/change-password`, requiring the user to update their credentials before accessing the dashboard.
5. *Multi-Table Academic Provisioning*: `createAccountAction` atomically links the authentication credential in `users` with academic records in `students` and `student_profiles` (or `teachers`), enforcing database constraints and returning temporary credentials with a 1-click clipboard copy dialog.

## 3. Caveats
- Next.js 16 introduces the Proxy convention for Middleware; exporting both `proxy` and `middleware` in `src/middleware.ts` and `src/proxy.ts` guarantees forward and backward compatibility.
- Ensure that port 3000 is not occupied by other development servers when running Playwright E2E tests locally.
