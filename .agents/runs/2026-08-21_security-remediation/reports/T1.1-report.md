## Change 1 — `getCurrentRole()` default-deny (C2)

**Before (index.ts:26-27):**
```ts
const envRole = process.env.APP_ROLE;
return envRole === "STUDENT" ? "STUDENT" : "ADMIN";
```
Anonymous caller with no cookie and no/any other env value ⇒ **ADMIN permissions**.

**After:**
```ts
// Default deny: unverified callers get least privilege.
return "STUDENT";
```
- No session ⇒ `STUDENT` (`ROLE_PERMISSIONS.STUDENT` is all-false), matching `getRolePermissions()`'s own fallback.
- The legacy `process.env.APP_ROLE` fail-open read was removed entirely; it can no longer elevate an unverified caller.
- Callers: every consumer goes through `getPermissions()`. Anonymous users now get zero-permission flags instead of admin flags. All admin/student pages render permission-gated UI from these flags, so they degrade safely.

## Change 2 — `APP_ROLE` cookie NODE_ENV-gated (C2)

**Before (index.ts:20-24):**
```ts
const cookieStore = await cookies();
const legacyRole = cookieStore.get("APP_ROLE")?.value;
if (legacyRole === "ADMIN" || legacyRole === "TEACHER" || legacyRole === "CR" || legacyRole === "STUDENT") {
  return legacyRole;
}
```

**After (pattern identical to `resolveTestFixturePersona`, session.ts:71-73):**
```ts
// Test fixture persona override (non-production only).
if (process.env.NODE_ENV !== "production") {
  const cookieStore = await cookies();
  const legacyRole = cookieStore.get("APP_ROLE")?.value;
  if (legacyRole === "ADMIN" || legacyRole === "TEACHER" || legacyRole === "CR" || legacyRole === "STUDENT") {
    return legacyRole;
  }
}
```

## Change 3 — `DEMO_STUDENT_ID` cookie/env NODE_ENV-gated (C2)

**Before (index.ts:50-58):** cookie `DEMO_STUDENT_ID` (or env) resolved a student row **in production** for any visitor — direct IDOR into another student's dashboard data.

**After:**
```ts
// Test fixture student override (non-production only).
if (process.env.NODE_ENV !== "production") {
  const cookieStore = await cookies();
  const envStudentId = cookieStore.get("DEMO_STUDENT_ID")?.value || process.env.DEMO_STUDENT_ID || null;

  if (envStudentId) {
    const student = await db.query.students.findFirst({
      where: (s, { eq }) => eq(s.id, envStudentId),
    });
    if (student) return student;
  }
}
```

## Change 4 — First-student-alphabetical fallback removed (C3)

**Before (index.ts:60-65):**
```ts
// Fallback: Pick the first student alphabetically
const fallbackStudent = await db.query.students.findFirst({
  orderBy: [asc(students.name)],
});

return fallbackStudent ?? null;
```

**After:**
```ts
return null;
```
Unresolved identity now yields a controlled empty state. Verified all four `resolveCurrentStudent()` call sites already handle `null`:
- `src/app/(student)/attendance/page.tsx:17` — "No Student Context Found" card.
- `src/app/(student)/page.tsx:31` — "No Student Context Found" card.
- `src/app/(student)/subjects/page.tsx:24` — `if (student)` guard; falls through to public subjects list.
- `src/app/(student)/subjects/[id]/page.tsx:84` — `if (student)` guard around enrollment check.
No caller can receive another student's row. Unused imports `students`, `asc`, `eq` removed.

## Change 5 — `resolveCurrentStudentId()` arbitrary-student fallback removed (C3)

**Before (assignments.ts:70-72):**
```ts
// 4. Default test student fallback
const firstStudent = await db.query.students.findFirst();
if (firstStudent) return firstStudent.id;
```
Teachers/admins (or students with no profile) submitting homework were silently written as **the first arbitrary student row** — cross-student data corruption.

**After:** those three lines deleted; execution reaches the pre-existing:
```ts
throw new Error("Student academic profile not found for this account.");
```
Both callers (`saveSubmissionDraftAction`, `submitAssignmentAction`) wrap in try/catch and return `{ success: false, message: error.message }` — graceful failure, no signature change, only the fallback lines touched as mandated.

## Residual risks / handoff to T1.2

1. `(student)` pages still have **no server-side auth gate**: `/attendance`, `/subjects`, `/` render empty-state cards for anonymous users instead of redirecting (safe but leaky UX); `/today` is protected only by `proxy.ts`. T1.2's `requireAuth` pass closes this properly.
2. `resolveCurrentStudentId()` now throws for teachers/admins — correct deny, but if product later wants teacher grading flows via this helper, a separate authorized resolver is needed (grading path currently uses different code).
3. Anonymous `getCurrentRole()` returning `"STUDENT"` keeps API shape stable; if any future code treats role presence as authentication proof, that would regress — prefer `getCurrentUser()`/`requireAuth`.
4. `admin/homework/page.tsx:50-57` serializing all submissions when identity unresolved (review finding C3 tail) is **not** fixed here — out of scope, flagged for T1.2.
5. Pre-existing repo-wide lint debt (63 errors) masks CI signal; recommend a separate cleanup task so security changes get clean lint gates.
